# AI-NAV-01 — первые сценарии, интерфейс и маскот

Дата: 20.10.2026. Владелец — designer. Статус: A «Напарник» и плавающий icon-only chat приняты пользователем; согласованная правка внесена в Figma и подтверждена скриншотами. Остальные сценарии остаются дизайн-концептом; React/API ассистента не реализованы, новая фаза реализации не одобрена.

Основания: [согласованная концепция](assistant-concept-2026-10-20.md), [архитектурный handoff](../../pulse-backend/docs/assistant-architecture-2026-10-20.md), [DESIGN](../DESIGN.md), [HANDOFF](HANDOFF.md). ## Направление и источник UI

Режим поверхности — Operate: помочь закончить рабочую задачу и вернуться к ней. Пользователь выбрал A «Напарник» и плавающую кнопку с одним знаком маскота справа снизу, без видимого слова «Помощник». Она открывает всплывающий чат над кнопкой с тремя различимыми результатами: ссылка, параметры/отчёт, шаг знакомства. Дополнительного обязательного выбора режима перед вопросом нет. Короткие ответы и структурированные параметры предпочтительнее длинного чата.

## Три стартовых сценария

**Найти раздел.** На «Где посмотреть риски?» помощник предлагает существующие «Тревоги» (`/ml-risk`). Если вопрос явно относится к одной разрешённой карточке, ссылка ведёт в `/wells/:PulseID?tab=overview`. Сам текст модели не становится произвольным URL. Ответ содержит понятное название назначения и источник/версию инструкции; ссылка открывается нажатием пользователя. Если скважина не выбрана, помощник предлагает её выбрать, не угадывает объект по номеру.

**Подготовить отчёт.** Первый согласованный с архитектором сценарий — реестр скважин XLSX, `report_type=wells_registry`. Запрос «Выгрузи реестр по текущим фильтрам» открывает редактируемую карточку параметров. Полный однозначный запрос не вызывает лишнего интервью; отсутствие нужного значения или неоднозначность приводит к одному точному уточнению с сохранением остальных параметров. Кнопка «Сформировать реестр» фиксирует показанный набор. Неподдержанные типы/поля/форматы объясняются до формирования; доступная альтернатива не подменяет исходную задачу молча.

| Параметр | Значения и поведение |
|---|---|
| Фонд | Рабочий / Показательный, только доступные. Текущий фонд виден, источник предзаполнения понятен. |
| Архив | Текущие / Архивные / Все; первоначальное значение `current`, если запрос или текущий согласованный контекст не задают иное. |
| Активность | Все (`active_only=false`) / Только активные. Это отдельный фильтр от архива. |
| НГДУ и цех | Разрешённые идентификаторы либо все доступные. Значения подписаны; закрытые объекты не перечисляются. |
| Поиск | Текст номера или ID Pulse, до 120 символов; обычное текстовое поле. |
| Порядок | ID по возрастанию / убыванию, имя по возрастанию / убыванию — только четыре поддержанных сортировки. |
| Формат и поля | XLSX, фиксированные `PULSE_ID, WELL_NUMBER, NGDU, CEX, ACTIVE, ARCHIVED_AT, RESPONSIBLE, REVISION`; формат — информация, не выдуманный список PDF/CSV. |

Нет параметра периода, фильтра риска, произвольных колонок и нового ML-расчёта. Смена фонда приложения не переписывает уже готовый результат: его фонд остаётся виден, для новой области предлагается обновить черновик и сформировать заново. Правка готовых параметров создаёт новый результат.

После серверной готовности панель показывает количество строк, параметры, дату формирования/среза и ограниченный preview. В макете — первые 3 строки и 4 из 8 фиксированных полей; действие «Все поля предпросмотра» относится к тому же результату. В архитектурном target предусмотрены страницы зафиксированных строк и XLSX из них. Число показанных строк и total различимы; просмотр не ограничивает незаметно состав файла. Время и срок доступности берутся из ответа, а не придумываются клиентом. До реализации снимка два независимых чтения существующих list/export не выдаются за согласованный результат. Скачать файл можно только после повторной серверной проверки доступа.

**Освоиться с приложением.** По «Покажи, как начать» маскот от первого лица проводит четыре шага: найти скважину → посмотреть риски → открыть телеметрию → найти сохранённые проверки. Первое действие — «Открыть Скважины», а не автоматический уход со страницы. Пользователь выбирает доступную карточку; при пустом фонде помощник объясняет поиск и фильтры, не подставляет случайную скважину. Шаги не запускают проверки и не записывают данные. Далее/назад/завершить/повторить доступны явно. Несуществующая, закрытая или ещё не отрисованная цель не подсвечивается как доступная. В макете нарисован первый шаг; остальные состояния маршрута описаны здесь, но не выданы за готовые интерактивные прототипы.

## Маскот

Три оригинальных векторных направления созданы непосредственно в Figma:

- **A, «Напарник» — выбран пользователем.** Синяя каска, светлый корпус и спокойный визор. Совместим с рабочим синим акцентом; компактная версия сохраняет каску и глаза. Полная фигура 56×64 на старте/в знакомстве, знак 24×24 в плавающей кнопке с областью нажатия 56×56. Видимой подписи на кнопке нет; доступное имя — «Открыть помощника». Прежняя кнопка 144×44 относится к предыдущей итерации Figma.
- **B, «Проводник».** Более округлый, с жестом приветствия и тёплой каской. Дружелюбнее, но активнее и ближе к цветовой семантике предупреждений.
- **C, «Инженер».** Геометричный корпус и строгая каска. Лучше как техническая пиктограмма, слабее как узнаваемый собеседник в 24 px.

Маскот не меняет знак Pulse, не обозначает степень риска и не сообщает готовность вместо серверного статуса. Он не ходит по экрану, не пульсирует, не появляется поверх тревог и не начинает разговор без запроса. Оригинальные SVG-источники совпадают с импортированными в Figma: [A](assistant-2026-10-20/mascot-a-naparnik.svg), [B](assistant-2026-10-20/mascot-b-guide.svg), [C](assistant-2026-10-20/mascot-c-engineer.svg), [A / 24px](assistant-2026-10-20/mascot-a-compact-24.svg). Локального альтернативного макета интерфейса не создавалось.

Кнопки — экземпляры исходных компонентов с высотой области 44 px. Цвета связаны с существующими Light/Dark modes; новые глобальные токены не создавались.

Открытие переносит фокус в заголовок/поле чата; доступное имя кнопки — «Открыть помощника», у закрытия — «Закрыть помощника», у отправки — «Отправить задачу». Состояние раскрытия связано с чатом; знак маскота декоративный для screen reader при наличии доступного имени действия. Невидимый контент не остаётся в tab-порядке. Чат немодальный: Tab доступен и рабочему экрану, и чату, фокус не запирается. Escape и закрытие возвращают фокус на плавающую кнопку. Переход по ссылке переводит фокус к заголовку открытого раздела; закрытие сохраняет форму, черновик и прокрутку. Focus ring заметен снаружи скруглённой кнопки и не обрезается; отдельный focus specimen ещё предстоит синхронизировать в Figma.

Enter отправляет непустой запрос; Shift+Enter добавляет строку; во время IME composition Enter не отправляет. Пустой/пробельный запрос отключает отправку. В форме Enter следует поведению формы и не отправляет параллельно новый чат-запрос. Новые ответы и готовность объявляются через polite live region без чтения всех строк; ошибки связываются с причиной и способом продолжения. Обычные loading/ответы не перехватывают фокус. Видимый focus ring в цвете темы обязателен; reduced motion убирает перемещение маскота и переход раскрытия панели. Эти требования описаны для будущей реализации, не проверены браузером.

## Состояния и продолжение работы

| Состояние | Текст/действие и правило |
|---|---|
| Loading | «Формирую реестр…», отмена; параметры сохранены. Нет выдуманных процентов и сообщения «готово» до ready. Повторный клик не запускает незаметный дубль. |
| API error / timeout / busy | «Реестр не сформирован», сохранить задачу/параметры; явные «Повторить» и «Изменить». Никакого пустого файла под видом успеха. |
| Unknown / ambiguity | Один точный вопрос или явный выбор поддержанной операции; неизвестное значение не превращается в default незаметно. |
| No access / revoked | Не раскрывать закрытые имена, строки или файл. Вернуть к доступной области; готовность старого результата больше не обещается. |
| Expired | «Срок результата истёк» и «Сформировать заново». Новый результат может содержать обновившиеся данные; старый не выдаётся за прежний срез. В state-board expired и no-access пока показаны общей карточкой, отдельные тексты нужны при реализации. |
| Empty | «Скважин не найдено», показать 0 и активные условия; можно изменить фильтры. По архитектурному target допустим пустой XLSX с заголовками; образцы и чужие скважины не подставляются. |
| Сервис ответов недоступен | «Продолжим без диалога»: обычные разделы, локальное знакомство и ручная форма реестра доступны. Размещение модели отдельно от backend не меняет пользовательский сценарий. |
| Смена пользователя | Очистить черновик, ответы и результаты; не показывать прошлую карточку/файл другому пользователю. |
