# Дизайн «Пульса скважины» перед переносом в React

[Figma](https://www.figma.com/design/km4tIbp3LnMTRrV6yi6Qho)

## Объём
Основные разделы, форма проверки и сохранённый результат; отдельные состояния расчёта, ошибок файла, недостаточности данных и обработки. Макеты 1440, 1280 и 1024 px. Общие состояния и состояния полей/кнопок. Значения демонстрационные.

## Прототип
Обзор → открыть скважину → отметить проверку → форма → сохранить → результат → очередь. Навигация связана с основными разделами. Это демонстрация переходов, не настоящий ввод, загрузка или сохранение.

## Уже есть в приложении
Реестр, оценки и объяснения, запуск расчёта, проверка CSV/XLSX, журнал API-запросов, статусы new/acknowledged/false_positive.

## Требуется дополнить API
Ответственный, комментарии, расширенные результаты проверки и история, событие отказа с датой, ремонты, экспорт отчёта, эксплуатационные агрегаты, измеряемый прогресс и роли. Наличие в макете не означает готовность этих функций.

## Правила
Оценка модели и статус обработки независимы. Подозрение не равно фактическому отказу. Недостаточность данных не равна норме. Исследовательские метрики отделены от эксплуатационных. Пропуски на графике — разрывы, не нули. Порог и число окон читаются из метаданных. Период собственной базы должен быть определён и раскрыт пользователю.

## Очерёдность переноса
Компоненты и состояния → навигация и списки → карточка и графики → загрузка → новые функции после уточнения API → адаптивность и доступность.

## Границы проверки
Проверены основные композиции, семантические цвета и связи переходов. Динамические фильтры и ввод в Figma не реализованы. Роли, состав отчёта и данные событий требуют продуктового согласования. Мобильный телефон не входит в этот проход. Полный аудит доступности проводится на реализованном приложении.
